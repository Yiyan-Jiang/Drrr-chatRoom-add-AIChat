# 测试约定

本项目只维护端到端测试或冒烟测试。原有后端 pytest/unittest、SQLite 内存库集成测试、前端函数测试和源码正则断言已移除。不要将这类测试改名后作为冒烟测试保留。

## 自动冒烟

在仓库根目录运行，使用 Node.js 22.9+ 和已安装的前端依赖：

```bash
npm --prefix frontend ci
# 按项目 README 启动本地服务，或使用现有 Compose 环境
docker compose up -d --build
npm run test:smoke
# npm test 运行相同流程
npm run test:smoke -- --help
```

需要真实、已应用 Alembic 迁移的 MySQL 以及可访问的前后端；脚本不启动服务，不修改数据库 schema，不绕过门禁或 JWT。请使用开发/测试环境，因为冒烟会创建临时账号、房间、消息和帖子。

| 环境变量             | 含义                  | 默认值                                           |
| -------------------- | --------------------- | ------------------------------------------------ |
| `CHAT_GATE_PASSWORD` | 目标后端的门禁密码    | 从本地 `backend/.env` 读取，已设置的环境变量优先 |
| `SMOKE_API_URL`      | 后端地址，不含 `/api` | `http://127.0.0.1:8000`                          |
| `SMOKE_WEB_URL`      | 前端地址              | `http://127.0.0.1:5173`                          |

PowerShell 示例（非默认服务地址时）：

```powershell
$env:SMOKE_API_URL = 'http://127.0.0.1:8000'
$env:SMOKE_WEB_URL = 'http://127.0.0.1:5173'
npm run test:smoke
```

`smoke.mjs` 复用 `frontend` 已有的 `socket.io-client`，从外部通过公开协议完成以下流程：

| 场景       | 成功条件                                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 前端可用性 | HTML 和页面脚本入口返回 200；此项不验证 React 渲染                                                                                      |
| 门禁与账号 | 未通过门禁/未登录请求被拒绝；通过真实 Cookie 注册两个临时用户并登录；错误密码被拒绝，用户响应不泄漏密码                                 |
| 群聊       | 创建房间，非房主修改被拒绝；两个独立 Socket 客户端加入，发送方收到 ack，另一方收到消息；HTTP 历史能读回消息，相同消息 ID 重试不重复入库 |
| 好友私聊   | 非好友加入私聊被拒绝；申请与接受好友、好友列表、双方加入私聊、ack 与实时投递、HTTP 历史读回                                             |
| 帖子       | 创建帖子，非作者删除被拒绝；评论、点赞、收藏可读回                                                                                      |
| 清理       | 断开 Socket，删除本次帖子、房间和账号并读回 404；相关消息、好友关系和评论由现有删除接口及 MySQL 外键清理                                |

每次运行使用唯一账号和消息标识，不依赖已有用户。正常完成或场景失败后都执行 `finally` 清理；业务失败、超时或清理失败均返回非零退出码。失败日志标明接口或事件，清理失败会输出资源名称和 ID，方便排查；不会输出门禁密码或 JWT。强制结束进程、网络响应丢失等情况下无法保证清理，请根据 `smoke_` 账号和测试记录在测试环境处理残留。

## GitHub 自动化

工作流在 [`.github/workflows/smoke.yml`](../.github/workflows/smoke.yml)，push、PR 和手动触发都会运行：

1. 安装前端依赖，执行 build 与 lint。
2. 在 GitHub runner 上生成临时门禁和 JWT 配置，使用现有 Docker Compose 启动全新的 MySQL、后端和前端；后端启动入口应用现有迁移。
3. 等待实际 HTTP 接口可用，再运行根目录 `npm test`，验证公开 HTTP / Socket.IO 业务链路。
4. 失败时输出服务日志；任务结束时清理服务和临时数据库卷。

工作流不依赖个人 `backend/.env` 或 GitHub Secrets，不连接部署环境的数据库。结果在仓库 Actions 和提交/PR 的 Checks 中查看。必须把工作流文件一起提交并推送，单独添加 npm 测试命令不会让 GitHub 自动执行。手动 Run workflow 按钮需要工作流已存在于默认分支。

云端当前自动运行真实服务冒烟；浏览器渲染与交互仍按以下清单人工检查，不宣称已有浏览器自动化端到端测试。

## 页面端到端人工检查

自动冒烟验证公开协议上的主要业务链路。涉及 UI、路由、登录态、滚动和断线重连的变更，用两个独立浏览器会话（普通窗口与无痕窗口）连接同一环境，记录涉及的场景及实际结果：

1. 未通过门禁访问登录页会回到门禁；正确密码后可以注册、登录，刷新保持登录，退出后受保护页面不可访问。
2. 两个账号进入同一房间，互发消息；消息只显示一次，刷新仍可读到，成员列表随加入/离开更新。
3. 建立好友关系并互发私聊；切换页面、刷新后历史可读，群聊与私聊内容不会串到其他会话。
4. 短暂断网再恢复，检查重连、发送状态与历史补齐；切换房间后，不再显示上一个房间的实时消息。
5. 创建帖子、评论、点赞、收藏，刷新检查状态，非作者不能删除。
6. 涉及新闻、留言板或个人资料时，检查对应页面加载、详情导航、编辑保存和失败提示。

## 维护规则

- 自动场景集中在 `tests/`，统一用根目录 `npm test` / `npm run test:smoke`；新增检查只调用运行中服务的公开协议。
- 不新增单元测试、集成测试、mock、SQLite、依赖覆盖或源码结构断言。
- 新增写入必须登记清理动作，清理顺序遵守资源依赖，并报告清理失败。
- 按变更范围运行冒烟和相关页面端到端检查。`npm --prefix frontend run build` / `lint` 是独立静态检查，不能替代业务验证。
- 环境不足或某项未执行时明确记录，不以构建通过推断业务测试通过。
