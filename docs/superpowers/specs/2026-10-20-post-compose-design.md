# 独立发帖页设计

## 已确认需求

- 桌面端从帖子列表的“＋”进入 `/posts/new`，替换原来的浮动发帖窗口。
- 独立全宽页面，保留新闻文章页式黑色品牌顶栏与浅色正文区域，不显示首页左右侧栏。
- 顶部填写标题；左侧为等宽字体的原生 Markdown 输入框，右侧实时预览；不增加编辑器依赖或格式工具栏。
- 预览右侧显示二、三级标题目录，目录随正文更新，点击只滚动预览区域。
- 编辑区、预览区、目录分别滚动，隐藏滚动条，保留滚轮、触控板及键盘操作；右下角发布按钮始终可见。
- 发布成功进入新帖详情。失败显示原因、保留内容并允许手动重试；请求进行中禁止重复提交。
- 有未发布标题或正文时离开需确认，放弃后不保存草稿；刷新或关闭使用浏览器原生提示，受浏览器交互限制。成功发布的跳转不提示。
- 移动端适配、草稿持久化、图片上传、修改已发布帖子、后端接口变更不在范围内。

## 实现边界

- 使用现有门禁与登录守卫、`postsApi.create`、`PostMarkdownArticle` 及新闻共享 Markdown 渲染器。
- 标题最多 80 字符、正文最多 20,000 字符，提交前去除首尾空白，空内容不能发布。
- 目录以实际渲染的 `h2`、`h3` 为准，忽略代码块中的伪标题，支持重复标题。锚点只属于预览，不触发路由离开确认。
- 沿用共享渲染器的 URL 筛选与代码高亮。输入不因异步渲染而阻塞；目录对应当前可见的预览。
- 站内导航通过 React Router 阻止器确认；成功后先解除脏状态再进入 `/posts/:id`。请求状态与错误由发帖页负责，不加载帖子列表来完成发布。
- 隐藏滚动条的样式限于新页面，不改变新闻页现有目录滚动条。
- 保留之前 Docker 修复的工作区改动，不混入本次提交。按用户要求每阶段一个 commit，使用中文 Conventional Commits，保留 Husky 检查，不推送或打包。

## 验收

1. 从真实帖子入口进入新页面；直接访问路由仍受认证保护。
2. 桌面页面不出现首页侧栏，编辑、预览、目录不互相遮挡；发布按钮不随内容滚走。
3. 标题、段落、列表、代码块及表格实时渲染；二、三级目录能更新，重复标题可分别定位，代码内标题不进入目录。
4. 编辑与预览独立滚动；点击目录只移动预览；滚动条不可见且滚动仍可用。
5. 空内容不能发送；请求进行中不能重复发送；失败保留输入并显示错误。
6. 站内返回的取消保留内容，确认丢弃后返回；刷新/关闭请求原生确认；空白页和成功发布不确认。
7. 通过真实本机接口创建临时帖子，确认详情页内容，随后清理本次测试帖子与账号。
8. 运行 TypeScript、ESLint 与相关格式检查；只执行冒烟和 E2E，不执行单元测试、不自动打包。
